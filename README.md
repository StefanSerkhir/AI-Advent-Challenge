# LLM CLI

Интерактивное Kotlin-приложение для работы с LLM через консоль. После запуска
оно остаётся активным: можно отправлять новые запросы, продолжать диалог и
менять параметры без перезапуска. Для HTTP-запросов используется Ktor.

Приложение поддерживает два эксперимента:

- сравнение ответа без ограничений и ответа с ограничениями формата;
- сравнение четырёх способов рассуждения над одной задачей: прямой запрос,
  инструкция «Решай пошагово», двухфазное создание промпта и группа экспертов.

В режиме `reasoning` модель дополнительно выступает независимым оценщиком:
сравнивает выводы, проверяет ошибки и называет наиболее точный способ. Всего
один такой эксперимент делает шесть API-запросов: четыре решения, отдельное
создание промпта и итоговая оценка.

Перед каждым из шести этапов CLI показывает прогресс. Для долгих генераций
HTTP-клиент ждёт ответ до 120 секунд вместо стандартных 15 секунд CIO. Временные
сетевые ошибки, статусы 408, 409, 429 и ошибки сервера 5xx повторяются не более
двух раз с экспоненциальной задержкой.

Для лимита токенов приложение автоматически использует параметр
`max_tokens` в DeepSeek и `max_completion_tokens` в OpenAI. DeepSeek также
получает `<END_OF_RESPONSE>` как API-параметр `stop`; выбранная OpenAI-модель
его не поддерживает, поэтому для неё действует явная инструкция в запросе.

После каждого запроса приложение выводит сравнительную таблицу:

```text
Результат сравнения
┌─────────────────┬──────────┬──────┬─────────┬───────────────┐
│ прогон          │ символов │ слов │ токенов │ finish_reason │
├─────────────────┼──────────┼──────┼─────────┼───────────────┤
│ без ограничений │      640 │   87 │     156 │ stop          │
│ с ограничениями │      172 │   24 │      48 │ stop          │
└─────────────────┴──────────┴──────┴─────────┴───────────────┘
```

Символы и слова считаются по тексту ответа. Колонка `токенов` использует
`completion_tokens`, а `finish_reason` приходит непосредственно от LLM API.
Если провайдер не вернул метаданные, отображается `н/д`.

## Четыре способа рассуждения

Включите режим и введите логическую, алгоритмическую или аналитическую задачу:

```text
/mode reasoning
> Сколько сравнений выполнит бинарный поиск в худшем случае для 1000 элементов?
```

Каждый способ получает независимый контекст:

1. исходный текст задачи без дополнительных инструкций;
2. исходный текст с инструкцией `Решай пошагово`;
3. запрос на создание эффективного промпта, затем новый запрос с полученным
   промптом;
4. запрос группе из аналитика, инженера и критика с отдельным решением каждого.

После четырёх ответов выполняется ещё один API-запрос для их сравнения. Для
произвольной задачи оценщик сначала решает её самостоятельно. Для встроенной
демонстрации используется проверенный эталон, который не передаётся четырём
решающим прогонам:

```text
/reason-demo
```

Демонстрационная задача — классическая задача о 100 шкафчиках. Правильный итог:
открытыми остаются 10 шкафчиков с номерами-полными квадратами.

В проверочном прогоне через OpenAI API все четыре способа дали правильный
итог. Прямой ответ был самым коротким, пошаговый и созданный моделью промпт —
полными и безошибочными, а группа экспертов допустила одну локальную оговорку о
направлении делимости. Финальный оценщик присудил ничью по точности пошаговому
решению и решению по созданному промпту. Конкретные формулировки и объём ответов
могут меняться между запусками.

Поддерживаемые провайдеры:

- `Deepseek` — модель `deepseek-v4-flash`, используется по умолчанию;
- `OpenAI` — модель `gpt-5.6-luna`; также поддерживается значение `ChatGPT`.

## Требования

- JDK 21;
- доступ в интернет;
- API-ключ выбранного провайдера;
- доступный баланс на аккаунте провайдера.

API-ключ можно создать в панели
[DeepSeek](https://platform.deepseek.com/api_keys) или
[OpenAI](https://platform.openai.com/api-keys).

## Настройка через `.env`

Создайте локальный файл конфигурации из примера:

```bash
cp .env.example .env
```

Можно сохранить ключи обоих провайдеров и переключаться между ними во время
работы:

```dotenv
llm_kind=Deepseek
deepseek_api_key=ВАШ_DEEPSEEK_API_KEY
openai_api_key=ВАШ_OPENAI_API_KEY
```

Для обратной совместимости поддерживается общий `llm_api_key`. Он относится к
провайдеру, выбранному через `llm_kind` или `--llm_kind`.

Файл `.env` добавлен в `.gitignore` и не должен попадать в репозиторий.
Ключи DeepSeek и OpenAI не взаимозаменяемы.

## Запуск

Для удобного запуска используется launcher `llm`:

```bash
./llm
```

Launcher скрывает служебный прогресс Gradle, поэтому в терминале отображается
только интерфейс приложения. Заголовок окна показывает активный провайдер —
например, `LLM CLI — OpenAI` — и обновляется после команды `/provider`.

После запуска появится приглашение для ввода:

```text
Интерактивный LLM CLI запущен. /help — список команд.

[Deepseek | compare | history=on]
> Почему небо голубое?
```

Можно передать первый запрос при запуске. После ответа приложение всё равно
останется активным:

```bash
./llm 'Почему небо голубое?'
```

В zsh символы `?`, `*` и `[]` имеют специальное значение, поэтому запрос с
ними нужно заключать в кавычки или запускать через `noglob`.

Провайдера и ключ можно указать прямо при запуске:

```bash
./llm --llm_kind=OpenAI --llm_api_key=ВАШ_КЛЮЧ Объясни корутины Kotlin
```

Стандартный интерактивный запуск через Gradle также доступен:

```bash
./gradlew run
```

Поддерживаются обе формы записи параметров:

```text
--llm_kind=OpenAI
--llm_kind OpenAI
```

## Интерактивные команды

| Команда | Описание |
| --- | --- |
| `/provider OpenAI\|Deepseek` | Сменить провайдера, сохранив историю |
| `/api-key <ключ>` | Задать ключ для текущего провайдера; ключ не печатается приложением |
| `/mode compare\|controlled\|unrestricted\|reasoning` | Выбрать режим ответа |
| `/reason-demo` | Запустить сравнение 4 способов на задаче о 100 шкафчиках |
| `/max-tokens <число>` | Изменить API-лимит контролируемого ответа |
| `/max-words <число>` | Изменить ограничение количества слов |
| `/format bullets <число>` | Изменить количество пунктов списка |
| `/stop <последовательность>\|off` | Изменить или отключить stop sequence |
| `/history on\|off` | Включить или отключить передачу контекста модели |
| `/reset` | Очистить историю обеих веток |
| `/settings` | Показать текущие параметры и размер истории |
| `/help` | Показать справку |
| `/exit` | Завершить приложение |

API-ключ, введённый через `/api-key`, хранится только в памяти процесса. Следует
учитывать, что сам терминал может сохранять введённые строки в своей истории.

## История диалога

История включена по умолчанию. В режиме `compare` приложение поддерживает две
независимые ветки: для ответа без ограничений и для контролируемого ответа.
Благодаря этому ответы разных режимов не смешиваются в контексте.

Режим `reasoning` намеренно не использует историю: все четыре способа должны
решать одну и ту же задачу независимо и не видеть ответы друг друга. Ответы
становятся общим контекстом только для финального оценщика.

`/history off` делает последующие запросы независимыми, но не удаляет уже
накопленную историю. После `/history on` диалог можно продолжить. Для полного
удаления контекста используется `/reset`.

История существует только в памяти и удаляется при завершении приложения.

## Входные параметры

| Параметр | Обязательный | Значение по умолчанию | Описание |
| --- | --- | --- | --- |
| `--llm_api_key` | Нет | Значение из окружения или `.env` | API-ключ начального провайдера |
| `--llm_kind` | Нет | `Deepseek` | Провайдер: `Deepseek`, `OpenAI` или псевдоним `ChatGPT` |
| Позиционный текст | Нет | Нет | Первый запрос; после ответа приложение продолжит работу |

## Переменные окружения

Вместо `.env` можно использовать переменные окружения:

```bash
export llm_api_key=ВАШ_КЛЮЧ
export llm_kind=OpenAI
./llm
```

Настройки применяются в следующем порядке приоритета:

1. CLI-параметры `--llm_api_key` и `--llm_kind`;
2. ключ конкретного провайдера: `deepseek_api_key` или `openai_api_key`;
3. общий `llm_api_key`;
4. значения переменных окружения имеют приоритет над одноимёнными значениями
   из `.env`;
5. `Deepseek` используется как провайдер по умолчанию.

## Структура

- `Main.kt` — создание и запуск интерактивного приложения;
- `llm` — launcher для запуска без `--args`;
- `app/` — настройки, выполнение запросов и история диалога;
- `cli/` — разбор параметров и интерактивные команды;
- `config/` — загрузка переменных окружения и `.env`;
- `network/` — создание Ktor-клиента;
- `llm/` — общий интерфейс, фабрика и реализации провайдеров.
