# LLM Workbench

Графическое Kotlin-приложение на Compose Desktop для диалогов с LLM и сравнения
разных способов генерации ответа. Приложение остаётся открытым после запроса:
можно продолжать диалог, менять режимы и настройки, просматривать предыдущие
результаты и запускать новые эксперименты без перезапуска.

Пользовательская иконка применяется к окну приложения и к нативным пакетам для
macOS, Windows и Linux.

HTTP-вызовы выполняются в корутинах вне UI-потока. Во время запроса приложение
показывает текущий этап и общий прогресс, блокирует повторную отправку и позволяет
отменить операцию. Ошибки API, сети и конфигурации отображаются внутри окна и не
завершают приложение.

## Возможности

Доступны два провайдера:

- DeepSeek, модель `deepseek-v4-flash`;
- OpenAI, модели `gpt-5.6-luna` и `gpt-4.1-mini`.

Провайдер и модель переключаются в боковой панели. Активная модель, провайдер,
API-ключи и параметры ответа сохраняются в локальном `.env`.

Поддерживаются пять режимов:

1. **Сравнение двух ответов** — независимые ветки без ограничений и с ними.
2. **С ограничениями** — маркированный список, лимиты слов и токенов, настраиваемая
   stop sequence.
3. **Без ограничений** — обычный диалог с моделью.
4. **4 способа рассуждения** — прямой ответ, пошаговое решение, решение по
   созданному моделью промпту и группа экспертов; шестой API-вызов сравнивает
   точность результатов.
5. **Сравнение температуры** — ответы при `temperature = 0`, `0.7` и `1.2`, затем
   итоговая оценка точности, креативности и разнообразия.

Для двух экспериментальных режимов доступны готовые демонстрации. Результаты
показываются карточками, а метрики — GUI-таблицей с числом символов, слов,
completion-токенов и `finish_reason`.

История включена по умолчанию и хранится в памяти. В режиме сравнения используются
две независимые ветки истории. Режимы рассуждения и температуры намеренно запускают
варианты в независимом контексте и передают ответы только финальному оценщику.

## Требования

- JDK 21;
- доступ в интернет;
- API-ключ выбранного провайдера;
- доступный баланс и право использовать выбранную модель.

Gradle Wrapper входит в репозиторий; отдельная установка Gradle не требуется.

## API-ключи и `.env`

Ключ удобнее всего ввести в скрытое поле **API Key** в приложении и нажать
**Сохранить ключ**. Значение сохраняется для активного провайдера в `.env` и не
показывается повторно в поле, логах или сообщениях об ошибках.

Можно подготовить файл вручную:

```bash
cp .env.example .env
```

Минимальный пример:

```dotenv
llm_kind=Deepseek
llm_model=deepseek-v4-flash
deepseek_api_key=ВАШ_DEEPSEEK_API_KEY
# openai_api_key=ВАШ_OPENAI_API_KEY
```

Для обратной совместимости поддерживается `llm_api_key`: он относится к активному
`llm_kind`. Специализированные `deepseek_api_key` и `openai_api_key` имеют
приоритет. Дополнительные параметры перечислены в `.env.example`; интерфейс
обновляет их автоматически.

`.env`, `.env.local` и `.env.*.local` исключены через `.gitignore`. Не заменяйте
пример в `.env.example` реальным ключом и не добавляйте локальный `.env` в Git.

## Запуск

Основной способ:

```bash
./gradlew run
```

Сохранён короткий launcher:

```bash
./llm
```

После запуска:

1. выберите провайдера и модель;
2. сохраните API-ключ, если он ещё не настроен;
3. выберите режим и параметры;
4. введите запрос и нажмите **Отправить** или `Ctrl+Enter` (`⌘+Enter` на macOS).

Настройки блокируются только на время активного запроса, чтобы параметры одного
эксперимента не менялись посередине выполнения. После завершения или отмены можно
сразу отправить следующий запрос.

## Сборка desktop-приложения

Создать запускаемый каталог для текущей ОС:

```bash
./gradlew createDistributable
```

Собрать переносимый uber-JAR для текущей ОС:

```bash
./gradlew packageUberJarForCurrentOS
```

Создать нативный пакет для текущей ОС (`.dmg`, `.msi` или `.deb`):

```bash
./gradlew packageDistributionForCurrentOS
```

Uber-JAR появляется в `build/compose/jars/`, а distributable и нативные пакеты —
в `build/compose/binaries/`. Нативный пакет нужно собирать на целевой ОС;
например, `.dmg` собирается на macOS. Для задач
`createDistributable` и `packageDistributionForCurrentOS` нужна полная поставка
JDK 21 с утилитой `jpackage`; урезанного JBR из Android Studio недостаточно.

## Проверки

Запустить все модульные тесты:

```bash
./gradlew test
```

Тесты покрывают исходную бизнес-логику режимов, независимые ветки истории,
ограничения запроса, метрики, HTTP-настройки, загрузку и сохранение `.env`,
безопасную обработку ошибок и переходы состояния desktop-контроллера, включая
защиту от повторной отправки и отмену.

## Структура

- `app/` — настройки, сценарии запросов, история, метрики и независимый от UI
  desktop-контроллер;
- `llm/` — интерфейс LLM и реализации провайдеров;
- `network/` — общий Ktor `HttpClient`, таймауты и повторы;
- `config/` — безопасная загрузка и атомарное сохранение `.env`;
- `desktop/` — только Compose-представление;
- `cli/` — изолированный прежний CLI-адаптер и его тесты; он больше не является
  точкой входа приложения.

Один общий `HttpClient` создаётся при старте и закрывается вместе с окном. Область
корутин контроллера также отменяется при завершении приложения.

## Сетевое поведение и ограничения

Таймаут ответа — 120 секунд. Временные ошибки, HTTP 408/409/429 и 5xx повторяются
не более двух раз с экспоненциальной задержкой. Отмена кооперативная: Ktor-запрос
обычно прерывается сразу, но окончательное прекращение зависит от текущего сетевого
этапа и платформы.

DeepSeek получает `max_tokens` и API-параметр `stop`. OpenAI получает
`max_completion_tokens`; для моделей без поддержки stop sequence ограничение
дублируется явной инструкцией. Температурный эксперимент с `gpt-5.6-luna`
сохраняет прежнее поведение и использует `gpt-4.1-mini`, потому что Luna принимает
только значение температуры по умолчанию.

История не сохраняется между запусками. Результаты единичного температурного
эксперимента иллюстративны; для статистических выводов нужны повторные прогоны.
Контрольный эксперимент также описан в [TEMPERATURE_EXPERIMENT.md](TEMPERATURE_EXPERIMENT.md).
