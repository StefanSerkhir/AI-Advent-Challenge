# LLM Workbench

Локальное web-приложение для диалогов с LLM и сравнения стратегий ответа.
Kotlin/Ktor выполняет запросы и хранит состояние, React + TypeScript + Mantine
отображает интерфейс в браузере. Готовый frontend раздаётся тем же Ktor-сервером,
что и API. Node.js backend, база данных и аккаунты не нужны.

## Быстрый запуск

Требования: **JDK 21+ для Gradle** (компиляция под JDK 21), **Node.js 22.12+**,
интернет для установки зависимостей и API-ключ выбранного провайдера.
При необходимости укажите `JAVA_HOME` на установленный JDK 21.
Gradle Wrapper входит в репозиторий.

```bash
./gradlew runWeb
```

Gradle установит frontend-зависимости из lock-файла, выполнит TypeScript-проверку,
соберёт UI при изменении исходников и запустит сервер. Откройте
[LLM Workbench](http://127.0.0.1:8080). Адрес также выводится в терминал.
`./llm` и `./gradlew :run` запускают web-приложение.
Остановка — `Ctrl+C`; сервер отменяет корутины и закрывает общий HttpClient.

Настройка порта (по умолчанию 8080):

```bash
./gradlew runWeb -PwebPort=8090
# или
WEB_PORT=8090 ./gradlew runWeb
```

Сервер слушает только `127.0.0.1`, не открывая приложение в локальную сеть.
Выберите провайдера и режим слева, сохраните ключ и отправьте запрос кнопкой или
`Ctrl+Enter` / `Cmd+Enter`. Содержимое экрана восстанавливается при обновлении
страницы; закрытие вкладки не отменяет генерацию. Для отмены используйте кнопку
«Отменить». Во время работы настройки и новый запуск заблокированы на сервере,
в том числе для других вкладок.

## Возможности

Доступны два провайдера:

- DeepSeek, модель `deepseek-v4-flash`;
- OpenAI, модели `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol` и
  `gpt-4.1-mini`.

Провайдер и модель переключаются в боковой панели. Активная модель, провайдер,
API-ключи и параметры ответа сохраняются в локальном `.env`.

Поддерживаются семь режимов:

1. **Сравнение двух ответов** — независимые ветки без ограничений и с ними.
2. **С ограничениями** — маркированный список, лимиты слов и токенов, настраиваемая
   stop sequence.
3. **Простой агент** — отдельная сущность `LlmAgent` принимает запрос, формирует
   сообщения, при включённой настройке учитывает историю, вызывает выбранную LLM
   через API и возвращает ответ в интерфейс.
4. **4 способа рассуждения** — прямой ответ, пошаговое решение, решение по
   созданному моделью промпту и группа экспертов; шестой API-вызов сравнивает
   точность результатов.
5. **Сравнение температуры** — ответы при `temperature = 0`, `0.7` и `1.2`, затем
   итоговая оценка точности, креативности и разнообразия.
6. **Сравнение моделей GPT-5.6** — один пользовательский промпт последовательно
   выполняют Luna, Terra и Sol, после чего Sol сравнивает анонимизированные ответы
   A/B/C. Для каждого вызова показываются время, input/completion/reasoning/total
   tokens и расчётная стоимость.
7. **Токены и контекст** — полностью локальные детерминированные сценарии короткого
   и длинного диалога, а также безопасная симуляция переполнения окна 6K.

Режим сравнения моделей всегда использует ключ OpenAI и независимые запросы без
истории с одинаковым `reasoning_effort=medium`. При выборе режима приложение
автоматически переключается на OpenAI и устанавливает рекомендуемый лимит не ниже
1000 токенов; затем лимит можно изменить вручную. Ошибка отдельной модели не
удаляет уже полученные ответы. Автооценка
помогает сопоставить качество, но не заменяет эталон или экспертную проверку.
Расчёт стоимости использует тарифы, проверенные 9 сентября 2026 года; перед финансовыми
оценками сверяйте актуальные цены в официальной документации:
[Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna),
[Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra),
[Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol).

Для двух экспериментальных режимов доступны готовые демонстрации. Результаты
показываются карточками, а метрики — GUI-таблицей с числом символов, слов,
completion-токенов и `finish_reason`.

История включена по умолчанию и сохраняется между запусками в версионируемом
UTF-8 JSON-файле `.llm-history.json` в текущем рабочем каталоге, рядом с `.env`.
В нём находятся роли, тексты и метрики успешно завершённых ходов; ключи, настройки
и промежуточные streaming-фрагменты туда не записываются. В режиме
сравнения используются две независимые ветки `unrestricted` и `controlled`.
Режимы рассуждения, температуры и сравнения моделей намеренно запускают варианты
в независимом контексте и в постоянную историю не входят.

JSON заменяется атомарно только после успешного завершения ответа. Ошибка или
отмена потока не меняет историю. Выключение настройки истории временно исключает
контекст из запроса и не записывает новый обмен, но не удаляет накопленные данные.
Кнопка очистки и `DELETE /api/history` очищают память и постоянный JSON. Если файл
повреждён, недоступен или имеет неизвестную версию, приложение показывает
безопасное предупреждение и начинает с пустой истории. Ошибка записи оставляет
прежний файл и память без нового обмена.

## Токены, контекст и стоимость

Токен — элемент представления текста моделью: это не обязательно слово или
символ. Один и тот же видимый текст может разбиваться по-разному разными
tokenizer и версиями моделей. В приложении строго разделены:

- `estimatedCurrentMessageTokens` — только новое сообщение пользователя;
- `estimatedHistoryTokens` — сохранённая история до нового сообщения, включая
  роли и служебный framing Chat Completions;
- `estimatedContextTokens` — весь активный контекст конкретного API-запроса;
- `actualInputTokens` — input usage, который фактически сообщил провайдер;
- `currentHistoryTokens` — текущий оценочный размер сохранённого диалога;
- `cumulativeApiInputTokens` — сумма фактически обработанного input всех вызовов.

Полная история отправляется снова на каждом ходе. Поэтому при контекстах 100,
200 и 300 cumulative input равен 600, а не размеру последней истории 300.
Интерфейс показывает это отдельно в карточке хода, сводке, таблице и диаграмме.

До сетевого вызова `TokenEstimator` считает estimate содержания, ролей и protocol
overhead. Для GPT-5.6 в JVM-проекте не используется неподтверждённый «точный»
tokenizer: заменяемый `unicode-chat-fallback-v1` явно помечен как приблизительный.
Он анализирует Unicode-сегменты и framing запроса, а не объявляет число символов,
слов или `length / 4` точным токенным значением. Estimate может отличаться от
usage API из-за другой версии tokenizer провайдера, скрытого служебного framing,
нормализации и особенностей endpoint. После `CompletionFinished` источником
истины становятся `prompt_tokens`, `completion_tokens`, cached/cache-write и
reasoning details из usage. Если usage отсутствует, UI показывает «н/д» — estimate
не подставляется вместо actual.

Стоимость вычисляется на backend через `BigDecimal` и версионированный профиль
цены. Из input сначала вычитаются cached и cache-write tokens, поэтому они не
оплачиваются повторно как uncached. Cache-write умножается на 1,25; reasoning
tokens не прибавляются второй раз к output, поскольку входят в completion usage.
При input строго больше 272K весь input получает коэффициент 2×, output — 1,5×.
Округление выполняется только при отображении. Если usage или ценовой профиль
неизвестен, стоимость равна `null`/«н/д».

Для GPT-5.6 Sol профиль содержит окно 1 050 000, max output 128 000, input
$4/1M, cached input $0,40/1M, output $20/1M и cache-write 1,25×. Значения
проверены 9 сентября 2026 года по [официальной странице GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol),
которая также подтверждает повышенный тариф после 272K. Аналогично заданы
[Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna) и
[Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra). Для
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)
заданы окно 1 047 576, max output 32 768 и цены $0,40/$0,10/$1,60 за 1M
uncached input/cached input/output. Профиль
[DeepSeek V4 Flash](https://api-docs.deepseek.com/quick_start/pricing/)
учитывает окно 1 048 576, max output 384K и автоматически выбирает официальный
peak либо off-peak тариф по UTC-времени вызова; выбранная ценовая версия
сохраняется с ходом. Для неизвестной модели приложение не выдумывает лимит или
цену, не блокирует запрос по фиктивному окну, но по-прежнему показывает
фактический usage.

Перед отправкой проверяется
`estimatedContextTokens + reservedOutputTokens <= contextWindow`. Requested max
output задаёт резерв: слишком большой резерв уменьшает доступный input-бюджет.
Политика `REJECT` (по умолчанию) локально отклоняет запрос, не вызывает LLM и не
меняет историю или cumulative суммы. `DROP_OLDEST` удаляет только из активного
API-контекста самые старые полные пары user/assistant; текущее сообщение и
постоянная история сохраняются. Legacy-сообщение без пары удерживается
детерминированно. UI показывает число и estimate токенов исключённых сообщений.
`finish_reason=length` означает исчерпание output-лимита генерации и не является
переполнением входного контекста. Ошибка, оборванный stream или отмена не создают
завершённый ход и не увеличивают totals.

Метрики записываются вместе с user/assistant обменом одной атомарной заменой
`.llm-history.json` формата v2: стабильный id, модель, estimate, actual usage,
finish reason, точная стоимость, версия цены и сведения о сокращении. Файл v1
продолжает загружаться; для его старых обменов actual usage и стоимость честно
показываются как «н/д». При отключённой истории API получает только текущий
запрос, обмен не сохраняется, а показатели помечаются как runtime-сессия без
истории и не смешиваются с сохранённым диалогом.

Три безопасных сценария запускаются кнопками в разделе «Готовые эксперименты»:

1. «Токены: короткий диалог» — 4 коротких хода.
2. «Токены: длинный диалог» — 14 предсказуемых ходов, хорошо видна разница между
   текущей историей и cumulative API input.
3. «Токены: переполнение 6K» — сначала `REJECT`, затем `DROP_OLDEST`; ранний
   `SENTINEL-ALPHA` исчезает из активного контекста, но остаётся в постоянной
   истории.

Окно 6K подписано как учебная симуляция и не является лимитом GPT-5.6 Sol.
Демонстрации используют локальный deterministic client, не требуют API-ключа и
не выполняют платных запросов. Для ручного запуска fixture используйте
`./gradlew runWebFixture`; обычный «Простой агент» запускается `./gradlew runWeb`,
после чего выберите модель, задайте max output и политику переполнения.

## API-ключи и `.env`

Ключ удобнее всего ввести в скрытое поле **API Key** в приложении и нажать
**Сохранить ключ**. Значение сохраняется для активного провайдера в `.env` и не
показывается повторно в поле, логах или сообщениях об ошибках.

Можно подготовить файл вручную:

```bash
cp .env.example .env
```

Минимальный пример:

```dotenv
llm_kind=Deepseek
llm_model=deepseek-v4-flash
deepseek_api_key=ВАШ_DEEPSEEK_API_KEY
# openai_api_key=ВАШ_OPENAI_API_KEY
```

Для обратной совместимости поддерживается `llm_api_key`: он относится к активному
`llm_kind`. Специализированные `deepseek_api_key` и `openai_api_key` имеют
приоритет. Дополнительные параметры перечислены в `.env.example`; интерфейс
обновляет их автоматически.

`.env`, `.env.local`, `.env.*.local` и `.llm-history.json` исключены через
`.gitignore`. Не заменяйте пример в `.env.example` реальным ключом и не добавляйте
локальные файлы приложения в Git.

## Разработка

Запустите backend, явно разрешив origin Vite:

```bash
WEB_DEV_PORT=5173 ./gradlew runWeb
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте [Vite dev UI](http://127.0.0.1:5173). `/api` (включая SSE) проксируется
на backend. Для других портов передайте одинаковые `WEB_PORT` и `WEB_DEV_PORT`
обоим процессам. В обычном режиме Vite не нужен. Произвольный CORS не включается.

## Готовая сборка

```bash
./gradlew installDist
./build/install/AIAdventChallenge/bin/AIAdventChallenge
```

В `build/install/AIAdventChallenge` находятся JVM-приложение и готовый frontend.
После сборки для запуска нужен только JDK/JRE 21+, Node.js больше не нужен.
На Windows используйте `gradlew.bat` и launcher `.bat` из `bin`.
`.env` читается и сохраняется в текущем рабочем каталоге запуска.

## Проверки

```bash
./gradlew test
npm --prefix frontend run typecheck
npm --prefix frontend run build
```

Существующие тесты бизнес-логики сохранены. Тест `a new runtime restores persisted
context before its first LLM call` создаёт два независимых `PromptRunner` с общим
только путём к временному JSON и проверяет восстановленный порядок
`user, assistant, user` без внешнего API. Также добавлены проверки формата,
атомарной замены, повреждения, очистки, отмены и ошибок записи. API-тесты всех режимов,
прогресса/SSE, настроек и ключей, идемпотентности, отмены, конкурентных команд,
валидации, локальной защиты и сохранения частичных результатов.

Браузерные проверки используют настоящий Ktor и детерминированный LLM-клиент,
временный `.env` и фиктивные ключи. Запросы к платным API не выполняются:

```bash
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

Playwright самостоятельно запускает `runWebFixture` на порту 18080. Проверяются
все шесть режимов, демо, горячие клавиши, история, перезагрузка во время запроса,
две вкладки, offline/reconnect, потерянный ответ POST, повтор после отмены,
ошибки отдельных моделей, Markdown/код/формулы и узкое окно. Этот клиент
расположен исключительно в `src/test` и не входит в production-сборку.
Для ручной проверки без ключей: `./gradlew runWebFixture`.

## Структура

- `src/main/kotlin/agent/` — агент, инкапсулирующий запрос, историю и ответ LLM;
- `src/main/kotlin/app/` — общий контроллер, StateFlow, сценарии и метрики;
- `src/main/kotlin/web/` — Ktor Server, явные DTO, REST/SSE, локальная защита;
- `src/main/kotlin/llm/`, `network/`, `config/` — исходные клиенты, HttpClient и `.env`;
- `frontend/src/components/` — представление, Markdown, настройки, карточки;
- `frontend/src/api/`, `state/` — типы, REST-клиент и синхронизация состояния;
- `legacy-desktop/` — изолированный Compose UI и его Markdown-тесты;
- `src/main/kotlin/cli/` — прежний CLI-адаптер и сохранённые тесты.

При необходимости Compose можно запустить отдельно:
`./gradlew :legacy-desktop:run`. Сборка нативных пакетов осталась в этом модуле,
например `./gradlew :legacy-desktop:packageDistributionForCurrentOS`.
Web runtime не содержит Compose и не открывает графических окон.

## Локальная безопасность

Ключи вводятся в браузере только для отправки на локальный сервер. После успешного
сохранения поле очищается; ключи не возвращаются API, не сохраняются в browser
storage, не включаются в bundle и не журналируются. Ответы и ошибки дополнительно
очищаются от известных ключей. Host/Origin проверяются по точному списку; для
изменений обязательны JSON и служебный заголовок. Raw HTML из LLM выключен,
KaTeX работает без доверенных команд; внешние картинки автоматически не загружаются.
При остановке сервера закрываются общие корутины и HttpClient.

## Сетевое поведение и ограничения

Таймаут ответа — 120 секунд. Временные ошибки, HTTP 408/409/429 и 5xx повторяются
не более двух раз с экспоненциальной задержкой. Отмена кооперативная: Ktor-запрос
обычно прерывается сразу, но окончательное прекращение зависит от текущего сетевого
этапа и платформы.

DeepSeek получает `max_tokens` и API-параметр `stop`. OpenAI получает
`max_completion_tokens`; для моделей без поддержки stop sequence ограничение
дублируется явной инструкцией. Температурный эксперимент с `gpt-5.6-luna`
сохраняет прежнее поведение и использует `gpt-4.1-mini`, потому что Luna принимает
только значение температуры по умолчанию.

Результаты единичного температурного эксперимента иллюстративны; для
статистических выводов нужны повторные прогоны.
Контрольный эксперимент также описан в [TEMPERATURE_EXPERIMENT.md](TEMPERATURE_EXPERIMENT.md).
